# 太空步专家与上层路由：2026-10-23 实验记录

后续时序路由、采样修正和 G 候选的最新证据见
`docs/moonwalk_router_temporal_20261023.md`；本文保留 B/C/D 原始实验记录。

## 当前结论

冻结原通用策略并训练独立专家有效：专家在现有太空步片段上的支撑稳定性和滑动配合明显
改善，通用模型 48 个保存张量保持不变。**当前逐帧自动 gate 还未通过任务验收。**
它在旧动作上影响很小，但频繁选择不合适的控制分支会削弱太空步机制。缓存一致性通过
不代表物理切换稳定，不能把独立专家的效果当作整个统一模型的效果。

## 专家学习 B

- 来源：完整复合试跑 `sliding_router_pilot_20261023_a/run/model_19.pt`。
- 学习：16 环境，500 次迭代，每次 32 步，共 256000 个环境转移，固定专家路由。
- 继承 v14 的脚底姿态、速度和接触目标，防滑惩罚为零；没有修改数据或摩擦。
- 原生 PPO 正常结束；采样显存峰值 3208 MiB，预算 6144 MiB，保留余量 4096 MiB。
- 最终模型：`test_outputs/sliding_router_specialist_20261023_b/run/model_499.pt`。
- 冻结检查：48 个通用网络/归一化/噪声张量全部不变；专家 36 个张量更新；gate 不变。

## 同参考、同协议的原生评测

参考是现有训练合成片段，490 个可用帧、9.8 秒，尚不是独立滑步泛化测试。
所有模式在同一评测配置下运行；关节/身体误差均比较完整相同时段。

| 模式 | 完成率 | 支撑脚超 0.1 m/s 比例 | 配对机制代理 | 全局身体误差 |
| --- | --- | --- | --- | --- |
| B：强制通用 | 100% | 58.99% | 10.43% | 905.87 mm |
| B：强制专家 | 100% | 2.88% | 44.96% | 422.28 mm |
| C：逐帧自动硬 gate | 100% | 34.17% | 7.91% | 766.38 mm |

脚底接近地面和速度均为运动学代理，NPZ 中没有逐脚接触力，不能称作已验证的接触机制。
评测来自 `sliding_router_eval_20261023_b_base`、`b_specialist_v2`、`c_hard_slide`
各自的 `metrics.json`，均位于 `test_outputs/`。

## 旧动作保持

保留的站立、走路、舞蹈、踢腿、出拳、跳跃共 11 个窗口：

- 强制通用：11/11 完成。
- C 自动硬路由：11/11 完成，8 个窗口的关节误差与强制通用完全相同。
- 其余 3 个窗口的关节 MAE 增加 0.00038–0.00044 rad；宏平均从 0.09881 到 0.09892 rad。

这支持当前旧动作回归的保持，但不能据此保证未见动作不受 router 误选影响。
冻结证据和自动路由误差应分开报告。明细在
`test_outputs/sliding_router_old_retention_comparison.json`。

## CPU gate 实验

C 使用两种控制分支下的滑步参考特征和普通动作负例，只更新上层 gate。
普通动作按原始动作分组保留；正例为同一合成动作的时间分块，并在边界间留出间隔。
两个控制器的任何保存张量均未改变。

保守阈值只按开发验证组选择；诊断保留组的滑步召回率 37.5%，普通动作误选率 0.45%。
闭环结果如上表，太空步机制未保留，C 不能作为最终自动路由模型。

D 尝试只对上层 gate 屏蔽“未来参考姿态相对机器人姿态”的 60 列，避免直接依赖跟踪偏差。
原通用/专家内部 router、输入和权重未改。这个对照在保守阈值下滑步召回率为零，
已拒绝继续 GPU 测试。屏蔽状态耦合信息本身没有解决识别问题。

离线时间平滑诊断表明误选可能随窗口增加而减少，但召回仍不足；尚未实现或验证运行时
时序 gate。不得把该探索诊断当成已验证的切换方案。
相关文件为 `sliding_router_gate_20261023_c/fit_report.json`、
`temporal_gate_diagnostic.json` 和 `sliding_router_gate_20261023_d_goal/fit_report.json`。
这些组已经用于开发诊断，最终泛化评估必须另留新动作，不能反复称为未见测试集。

## 参考目标内部的一致性

在相同角色标签下，参考轨迹自身的支撑脚平均水平速度约 0.218 m/s，超过 0.1 m/s 的
比例约 96.4%。因此“完全跟踪这份参考的支撑脚速度”和“支撑脚固定在地面”并不一致。

已经交叉核对关节顺序和坐标：MuJoCo 正向运动学与 NPZ 参考脚部中心位置的最大误差
约 1.2 微米。因此不能简单把这个结果归因于关节顺序或模型坐标出错。它仍是运动学目标
一致性检查，不是物理可行性证明；角色标签也需作为任务意图解释。
证据在 `sliding_router_reference_mechanism_geometry.json` 和
`sliding_router_reference_fk_crosscheck.json`。

## 继续推进

1. 保留 B 专家作为有效对照；不要把 C 或 D 标为完成版。
2. 改善路由的任务意图/时间上下文与切换连续性，使用开发验证组选择策略，另留新的旧动作
   和滑步参考作最终评估；不能只降低阈值让旧动作误选增加。
3. 审查参考角色对应的足端目标，区分参考里的意外滑动与期望滑动；必要时用独立配置
   验证按角色修正的目标，保留原数据和 B 奖励作为对照。
4. 在新的自动路由版本通过后，评估连续的普通动作→滑步→普通动作衔接，再考虑完成任务。

所有 GPU 工作串行执行，并有共享显存监控；没有停止其他人的任务，也没有运行真实机器人。
定时跟进保持启用，任务仍在进行。
